# Using it day to day

Putting the controls in place once is not the hard part. A Type II report tests
that they kept working, every week of the period.

## Every week

- Look at the **Dashboard**. Anything red is late. Anything amber is due within
  a week. Anything grey is missing, such as a criterion with no evidence.
- Log new **Incidents** the day they happen, and close them with what was done.

## Every time a recurring control runs

Add the evidence the day it happens, with the date it was produced, and link it
to the criteria it proves. For example:

- A quarterly access review: the export, the reviewer's sign-off and the
  tickets for access removed.
- A monthly vulnerability scan: the report and the tickets for what was fixed.
- A new starter: their background check and training record.
- A leaver: the ticket showing their access was removed, and when.

An auditor samples these. One missing occurrence is an exception.

## When something changes

- **A new system in the boundary:** add it to Assets and make sure access
  reviews, scanning and change management cover it.
- **A new vendor that touches customer data:** add it to Vendors, get their
  SOC report, and set the date you assessed them.
- **A changed policy:** change the version number and the approval date. The old
  version is kept in its history.

## Every quarter

Test a sample of controls yourself and record the result on each criterion. Fix
anything that fails before the auditor finds it, and raise it in
**Exceptions** so the fix is tracked.

## Every year

Review policies, vendors, the risk assessment and the system description. Run
the incident response exercise and a restore test. Then the next SOC report
period begins.
